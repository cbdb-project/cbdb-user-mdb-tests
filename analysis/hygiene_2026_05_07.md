### Why they kept showing as "modified" in `git status`

The `test_report_screenshot_consistency_audit_clean` test
**writes to the in-repo paths** every pytest run. Because
`reports/generate_report.py::ISSUES` has grown (Issues #20 +
#21 + #22 added since `820f4d0`), the regenerated `n_issues_total`
no longer matches the committed value — so each pytest run leaves
the working tree dirty on these two files. That dirty state then
followed every subsequent PR's `git status` output.

### Action taken in this hygiene PR

Commit a one-time refresh of the audit output (`n_issues_total:
19 → 21`, plus the timestamp). This is the smallest possible
change: regenerated by `python analysis/audit_report_screenshot_consistency.py`
and verified to contain exactly one factual delta plus one
generated-timestamp line. Going forward, the working tree will
stay clean until the next time a new Issue is filed — at which
point the next maintainer-side PR can include the refresh in the
same commit that added the Issue, instead of letting it
accumulate as ambient drift.

### What this hygiene PR explicitly does NOT do

- Does NOT modify the audit script.
